Blockies / Reference

Glossary

Every term the architecture uses, in one place. If a page uses a word you have not seen, it should be here.

absence
Not having a record at all, as opposed to having one whose value is null. An unplaced entity is absent from the placement table. → The document
alias
A public name on a Composite that points at a member's port or at a fold. It has no state, which is why a Composite needs no ports of its own. → Composites
archetype
A Type's visual identity: a shape descriptor plus the renderer package that draws it. → Types
assignability
Whether every value a source type can produce is accepted by a target type. Directional: integer is assignable to number, not the reverse. → Types
attention
What is being watched. Derived from session scopes and from a Run's declared input bindings; grants nothing and implies nothing. → Relationships
authority
A grant permitting a verb on a scope. Checked once when an event or command enters the World. → Relationships
blocked
The state of a computation that cannot run because a required input is unavailable. Never silently replaced by a default or a stale value. → Runtime
causation
The id of the event that directly caused a new event. Lets you reconstruct why something happened. → Processes
chrome
Decorative bounds, labels, and affordances around an assembly. Never interactive. → Space
claim
A Run's exclusive ownership of a host event input. Claimed deliveries go to the inbox; unclaimed ones go to the reducer. → Processes
committed generation
One snapshot of state and outputs that a transaction has made the new truth. Renderers read only committed generations. → Runtime
Composite
An explicit assembly of Blockies and nested Composites. Not a Blockie, not a Type, no ports of its own. → Composites
compute
A pure function that turns state, configuration, and inputs into output values. Cannot change state or emit events. → Types
configuration
Typed, author-edited settings belonging to a Blockie. Distinct from Model State, which only its reducer changes. → Types
coordinate scope
The thing a position is measured relative to: the Frame, or an owning Composite. → Space
definition
An immutable blueprint. Two kinds: a Type package (for Blockies) and a process definition (for Runs). → Entities
derived value
A value computed from stored records and never stored itself, such as occupancy, footprint, or display status. → Entities
digest
A content hash that pins an exact version of a definition, so behaviour cannot change underneath a World. → Types
dispatch
A manager's ability to send an addressed event to one member, chosen from a declared member set. The only thing management grants. → Processes
dissolve
Removing a Composite while preserving its members. Placements are converted to the parent scope and the interface is discarded. → Composites
effect
An authorised operation outside the deterministic World, such as a network call. Requested by a reducer, executed only after commit, and answered by a later event. → Runtime
entity
A thing with identity that exists in its own right. Blockies, Composites, and Runs are the runtime entities. → Entities
epoch
A counter on a manager designation that increments on every change, so a stale grant can be rejected. → Composites
fan-in
Many producers into one input. Forbidden implicitly, because the combining rule would be undeclared. A fold is the declared form. → Composites
fan-out
One output to many inputs. Always allowed. → Types
fold
A declared aggregation over a set of member value outputs: sum, count, min, max, collect. Uses no process and no shared state. → Composites
footprint
The derived world-space bounds of an assembly. Not stored, and never a membership test. → Space
Frame
The single root coordinate scope of a World. → Space
grant
A verb plus a scope, held by a role or by a Run. → Relationships
grouping
A Composite assembled ad hoc from existing entities. Mutable membership, preserved identities. → Composites
idempotent
Safe to perform twice with the same effect. Inbox deliveries are at-least-once, so a step must be idempotent or say otherwise. → Processes
inbox
The ordered queue of deliveries a Run has been sent. Durable across restarts. → Processes
layer
A number on a placement that orders members for drawing within one scope. Presentation only. → Space
manager
The one member of a Composite authorised to dispatch to other members. Must be a direct member and occupied. → Composites
materialisation
Turning a template into real instances and relationships, with fresh identities. → Composites
member
An entity directly contained by a Composite. → Composites
membership
The explicit fact that an entity is directly inside a Composite. Never inferred from proximity or appearance. → Composites
Model State
Persistent data owned by a Blockie, changed only by its own reducer. → Types
occupancy
Whether a Blockie currently hosts an unfinished Run. Derived from the registry, never stored. → Entities
opaque identifier
A string the system never parses or derives, used only for stable identity. → Entities
outbox
The committed queue of effect requests waiting to be executed after commit. → Runtime
placement
A position and scale relative to a coordinate scope. Optional, and semantically inert. → Space
policy
The roles and grants a World declares. Governs sessions, not the file holder. → Relationships
port
A typed socket on a Blockie: a direction and a kind (value or event). → Types
principal
The acting identity a host issues to a session. Never a World entity. → Relationships
producer
The one thing allowed to write a value output: the Type's compute, or an attached Run. → Types
provenance
Where a membership edge came from: an ad-hoc grouping or a specific template node. → Composites
pure
Same inputs, same outputs, no side effects. No clock, no randomness, no network. → Types
reducer
A pure function that takes state, configuration, and one event, and returns the complete next state plus any actions. → Types
renderer package
A drawing-only plugin. Not a Type: it has no ports, state, or logic. → Space
repair
An unambiguous fix applied at load instead of rejecting the document. Exactly one case: a dangling manager designation. → The document
Run
A managed, resumable activity with its own identity, state, inbox, and status. Hosted by exactly one Blockie. → Processes
run state
The state owned by a Run. Separate from the host Blockie's Model State, so there is only ever one writer. → Processes
staging
Working on a private copy of the World during a transaction, invisible to readers until commit. → Runtime
step
One bounded execution of a Run: receives a snapshot, returns a result, never spans a commit. → Processes
template
A pinned definition's internal structure, instantiated into fresh members with immutable topology. → Composites
transaction
A bounded unit of work that commits completely or changes nothing. → Runtime
transform
Translation plus uniform scale. No rotation, because rotation with non-uniform scale cannot compose losslessly. → Space
Type package
The immutable blueprint for a Blockie: archetype, state and config schemas, ports, optional logic. → Types
unplaced
Having no placement record: exists, is not drawn, contributes no footprint. → Space
value vs event
A value is the latest information; an event is a discrete occurrence. An event cannot be modelled as a value that stays true. → Types
wait condition
What must happen before a Run continues: an inbox item, a value change, a timer, a human answer, or an external service. → Processes
