Blockies / Concepts

Types, state and ports

A Type is the blueprint a Blockie is made from. It decides what the Blockie looks like, what data it holds, and what it can talk to.

A blueprint, not a thing

A Type package is immutable and digest-pinned: a World refers to one exact version, and changing the Type means publishing a new version. Nothing silently updates underneath a running World.

Three kinds of data

This is the most common source of confusion, so it gets a table.

DataBelongs toChanges howExample
Configuration the Blockie edited by an actor "currency: IDR", "label: Revenue"
Model State the Blockie only through its own reducer a counter's current count
Run state a Run only by that Run's steps a worker's current plan, checkpointed

They are separate on purpose. If a Run could write the Blockie's Model State, one entity would have two writers, and "what is the value" would depend on timing. See Processes.

Ports: the only way in or out

A port is a typed socket. Every port has a direction and a kind.

KindMeansExample
value the latest information, like a variable result: boolean
event a discrete occurrence, like a message on_press: {}

An event is not a value that happens to be true right now. "The button was pressed" cannot be represented by a boolean that stays true, because the second press would be invisible. That is why the two kinds exist.

Who produces a value

A value output declares exactly one producer:

  • compute — the Type's own pure function produces it;
  • process — only an attached Run may publish to it.

One producer, never both. If both could write, the value would depend on execution order. A process port with no attached Run is unavailable, and its consumers are blocked — never a stale value, never a default.

Who may own an input

An event input may declare claimable: true. That means an attached Run may take ownership of it: deliveries go to the Run's inbox instead of the Blockie's reducer. It is exclusive — reducer-owned or run-owned, never both.

This is the mechanism that stops an event from being handled twice. Full story in Processes → claims.

Compute and reduce

A Type may supply two optional functions.

compute

Takes state, config, and input values. Returns output values. It cannot change state, emit events, or talk to the outside world.

reduce

Takes state, config, and one event. Returns the complete next state, plus any events, dispatches, and effect requests. It changes only its own Blockie's state.

Pure

A function is pure when the same inputs always produce the same outputs and nothing outside is touched. No clock, no randomness, no network. Purity is what makes a World reproducible: two machines given the same inputs must agree.

Types of values

Values are described by the Blockies Type System: primitives like integer and decimal, and composite types like records, arrays, and unions. Two rules matter for learning:

  • Assignability — a connection is legal only if every value the source can produce is accepted by the target. Direction matters: integer fits number, not the other way round.
  • No implicit conversion — "1.5" never becomes 1.5. A silent conversion is a bug that appears months later, so a conversion must be an explicit Blockie.

Terms on this page

  • Type package — the immutable blueprint for a Blockie.
  • Archetype — the visual shape plus which renderer package draws it.
  • Digest — a content hash that pins an exact version.
  • Pure — same inputs, same outputs, no side effects.
  • Producer — the one thing allowed to write a value output.
  • Assignability — whether a source type safely fits a target type.

Check yourself

Why can't a Type have both compute and a Run producing the same output?

Because then two writers decide the value, and the result would depend on which ran last. The producer declaration forces the choice to be made once, at design time.

What happens to a process output when its Run finishes?

It becomes unavailable. Consumers are blocked rather than reading the last value, because the last value no longer describes anything that exists.

Why is "no implicit conversion" a feature?

Because coercion hides mistakes. A World where "1.5" silently becomes a number will eventually produce a wrong chart with no error anywhere.
