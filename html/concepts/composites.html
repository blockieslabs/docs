Blockies / Concepts

Composites

A Composite is an assembly. It is not a Blockie, it has no shape of its own, and it owns no ports. That sounds like a weakness until you see what it buys.

Running example

The dashboard is a Composite. It groups the button, two counters, and the gauge, exposes three aliases, declares a fold, and designates a manager. It has no Blueprint and no state of its own.

What it is

A Composite holds membership edges to Blockies and to other Composites, an alias table describing its public face, optional folds, an optional manager designation, and an optional presentation record.

The analogy is a labelled box. The box has a label, a list of contents, and maybe a person responsible for it. The box is not one of the contents. If you pick up the box, you pick up the things inside it, but the box does not become a thing inside itself.

Membership

  • Explicit. Being next to something, or looking like it, never creates membership.
  • One parent. A Blockie or Composite is a direct member of at most one Composite. Standalone is a normal state.
  • Acyclic. Containment cannot loop.
  • Provenanced. Each edge records whether it came from an ad-hoc grouping or from a pinned template.
  • Non-destructive. Removing a member does not delete it. It keeps its identity, state, placement, and Run.
  • Never empty. Removing the last member dissolves the Composite in the same transaction.

Membership is not placement, and neither is nesting. Three separate facts:

Two Blockies can be at the same coordinate and not be members of the same Composite. Two members can be on opposite sides of the Frame. Geometry never implies membership (C-23).

Aliases: the public face

A Composite has no ports. It has a table of aliases, each pointing at something that already exists: a member's port, or a fold.

aliases:
  press    -> button.on_press
  total    -> fold(sum, [counter1.count, counter2.count])
  display  -> gauge.display

Alias rules

  • A public value output has exactly one source. Never two.
  • A public value input may fan out through several alias entries, each with one target.
  • A public event output may have several sources; events are channels.
  • Chains resolve outward-in through nesting and must terminate. Cycles are invalid.
  • External consumers see the Composite's alias, never a member id.
Why aliases instead of real ports

Because a second port system would need its own types, its own bindings, and its own state to keep in sync with the members. An alias has no state, so there is nothing to sync and nothing to disagree with.

Folds: declared aggregation

A normal value input accepts one producer. That rule is what makes values predictable — and it makes SUM(A1:A10) impossible, because summing is many-into-one.

A fold is the declared exception: a Composite may aggregate a named set of same-typed member outputs with one operation — sum, count, min, max, collect. It runs in the runtime, uses no process, and shares no state.

fold total:
  operation: sum
  selects:   [counter1.count, counter2.count]
  result:    integer

Aggregation becomes explicit rather than implicit. That is the difference between a fold and a free-for-all. The fold is revalidated on every membership change: every selected member must still expose the declared port with a compatible type (S-29).

The manager

A Composite may designate zero or one manager. The manager is one of its members — not an outside brain attached to the group.

Requirements

  • It must be a direct member.
  • It must be occupied — its Run must be active.
  • Designation carries an epoch so a stale grant can be rejected.

What does management actually grant? Exactly one thing: composite.dispatch — the ability to send an addressed event to a member, chosen from a declared member set.

Everything else already works without authority:

  • publishing a Composite output — the manager's Run publishes to its own host port, and an alias picks it up;
  • observing member outputs — through its own input ports, wired by connections;
  • changing appearance — publish a value; a Run never writes the document.
What a manager cannot do

Add, remove, move, or reparent members. Read member state or configuration. Reach into a nested Composite. Cancel a member's Run. Write any part of the document, including presentation.

When the manager dies

Five things must happen in one committed generation:

  1. the Run becomes terminal;
  2. the host Blockie becomes vacant;
  3. the designation is cleared;
  4. the dispatch grant is revoked;
  5. outputs that depended on it become unavailable.

Split any one of those into a second transaction and you get a Composite claiming a manager that no longer exists.

Nesting

A Composite can contain another Composite. The parent sees the child's public aliases and nothing else. The child has its own manager, and the parent's manager gains no authority over it. If the child's manager dies, the child becomes unmanaged; the parent is untouched.

A "sales" Composite inside the dashboard could expose total and display to the dashboard. The dashboard's manager can dispatch to the sales Composite's aliases, but it cannot address the sales Composite's counters directly.

Common mistakes

  1. Treating the Composite as a member. It is the box, not a thing in the box. A Composite can be a member of another Composite, but not of itself.
  2. Confusing membership with placement. A Blockie can be placed inside a Composite's bounds without being a member; a member can be placed far away.
  3. Giving the Composite ports. Its interface is the alias table. A second port system would duplicate types and state.
  4. Expecting the manager to own the members. It has one grant: dispatch. It does not own member state, membership, or presentation.
  5. Leaving an alias dangling. Removing a member that an alias references must repair or reject the interface in the same commit.

Check yourself

Why does a Composite not have its own ports?

Because ports imply state and ownership. Aliases point at ports that already exist, so there is one source of truth and nothing to keep in sync.

Your manager publishes a value. Did it need special authority?

No. It published to its own host's process port, and an alias exposed it. Only dispatch needs a grant.

You remove a member that an alias points at. What must happen?

The same transaction must repair the alias or reject the change. Leaving a dangling alias would mean the Composite's public face refers to something that no longer exists.

What is the difference between a grouping and a template?

A grouping assembles existing entities and stays mutable. A template creates fresh identities from a definition and is immutable for the instance; to change it, fork it into a grouping.

Can the dashboard's manager dispatch to a nested Composite's member?

No. It can dispatch to the nested Composite's public aliases, not to its members. The parent's authority stops at the child's interface.
