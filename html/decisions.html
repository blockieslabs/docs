Blockies / Reference

Decision log

Forty-seven decisions, each recording what was chosen and why. The log is append-only: a later decision supersedes an earlier one, it never rewrites it.

Read a decision as: what changed, and what would have gone wrong otherwise. Two are superseded and kept deliberately, because the trail explains why the final answer is what it is.

Vocabulary note

D-046 renamed the words. This page uses the current terms: Blueprint for the old "Type package", value type for a BTS type, appearance for "archetype", and Blockie state for "Model State". The source decisions keep their historical words.

How to use this page

Skim the titles. When one surprises you, follow its link into the concept page. The concept pages teach the model; this page explains the choices behind it.

Foundations

D-001 active

Grouping and instantiation are different operations

Ad-hoc assembly keeps identities and stays mutable; instantiating a template creates fresh identities and freezes topology. One operation cannot serve both, because agents need to rearrange things constantly and reusable pieces need to be reproducible. Composites

D-002 active

Run state is separate from host Blockie state

Otherwise one Blockie has two writers and "what is the value" depends on timing. Processes

D-003 active

Composites may be static

A Composite does not need a manager to be useful. Interface wiring is declarative; only coordination needs a computing member. Composites

D-004 active

Explicit state, with two bounds

Every state that carries transition authority is explicit. Derived projections and view ephemera are not state, and storing them guarantees two writers. Runtime

D-005 superseded by D-013

Every managed process is represented

The intent survived; the mechanism did not. A boolean became stage/backstage, which became nullable placement. Space

D-006 active

Geometry is semantically inert

Placement may change what you see, never what happens. Randomising every coordinate must leave the execution trace identical. Space

D-013 active

Host is mandatory, placement is nullable

The host Blockie is a Run's interface to the World, not its picture. Hiding a Run is a placement change, not a deletion. Space

D-034 active

Absence encodes unplaced and dissolved

Absent and null are different values everywhere, so a missing placement must be missing. The document

Composites

D-015 active

A Composite interface is an alias table

No second port system. Aliases point at member ports or folds and hold no state, so there is nothing to keep in sync. Composites

D-018 active

Management grants dispatch, nothing else

Everything else a manager needs already works through ordinary ports. The one thing static wiring cannot express is choosing which member to poke at runtime. Composites

D-025 active

Fork rewrites provenance; save-as captures structure only

Forking an instantiated Composite must not leave edges claiming a template that no longer applies. Saving a grouping captures structure and config, never state. Composites

D-026 active

Empty Composites dissolve; folds revalidate

A committed Composite always has at least one member. A fold whose member set changed must be revalidated in the same transaction. Composites

D-032 active

Dispatch is not a Composite alias source

Exposing it would let external actors address members directly, which is exactly what the boundary exists to prevent. Composites

D-033 active

The dispatch endpoint is a grant, not a port

No new port kind, no addressed port. The grant carries a member set, so possible routes stay statically validatable. Processes

D-035 active

Composite presentation is a record, not a Blueprint

A Composite has no Blueprint, so it carries a label, an optional renderer package, and an optional body member. Never styling, never a hidden definition. Space

D-036 active

Chrome is never interactive

A decorative surface has no owner, so no authority can attach to it. Only Blockies are hit-tested. Space

D-037 active

A Composite's own appearance is static per revision

A Run never writes the document. Anything dynamic must be a member that renders the change. Space

D-038 active

Members draw above the assembly; layer orders members

Overlapping members had no defined order at all until presentation work exposed it. Space

Processes

D-016 active

Claim routing decides reducer versus run

An event input is reducer-owned or run-owned, never both, so nothing is handled twice. Processes

D-017 active

Host output ports declare their producer

Compute or process, never both, and an unattached process port is unavailable rather than stale. Blueprints

D-029 active

Process phase scheduling and failure classes

Ready runs are FIFO, one step each per transaction, and execution failure is local while contract violation is fatal. Processes

D-030 active

Runs never observe mid-transaction values

Values stabilise after the process phase, so a step always reads one coherent generation. Glitch-freedom by construction. Processes

D-039 active

The step result is a three-way outcome

Terminal, waiting, or continue. The third case is how loops are expressed without a special flag. Processes

D-040 active

The step context includes configuration, never host state

Configuration is declared and construction-shaped; Blockie state changes under the reducer and would have no dependency edge. Processes

Space and views

D-007 active

One World, global placement, views are cameras

A view frames a region; it does not copy or reflow. That is how a presenter screen and an audience phone show different parts of one World. Space

D-008 superseded by D-013

Representation is stage/backstage

The step where "not drawn" stopped being a run state. Kept because the lineage explains the final answer. Space

D-022 active

Hierarchical local coordinates, translation and uniform scale

Rotation composed with non-uniform scale is not closed, so rotation is deferred rather than made lossy. Space

D-023 active

Placement operations are atomic

Group move, reparent, assign, clear, dissolve-convert. A partially moved group is a corrupt World. Space

D-024 active

Camera and grant scope are unrelated

Framing a region confers nothing. Authority is an explicit set of entities, ports, and verbs. Relationships

Data and status

D-010 active

Status is a projection with many dialects

One internal status, many exporters. Terminal-status protocols are lossy in different ways, and the World's vocabulary is richer. Entities

D-014 active

Primary status is derived, never declared

A declared status can lie; an observed one cannot. Entities

D-019 active

One status chain: registry, mode, display

Registry states project to occupied/vacant, then to seven display words. "Computing" was retired because a queued run is not computing. Entities

D-020 active

Value equality is typed

Propagation depends on knowing whether a value changed. Decimal equality is numeric, so a scale-only change does not propagate. Runtime

D-021 active

Inputs resolve from the staged generation

A downstream computation must not read last generation's value when this transaction already changed it. Runtime

Relationships

D-009 active

Attention is derived, not an entity

Who is looking is a function of sessions and bindings. A separate entity would be a second truth about who is working on what. Relationships

D-031 active

Attention is bindings plus sessions

Completes D-009: an in-world supervisor attends through its input bindings, not a session. Relationships

Performance and aggregation

D-011 active

Declared graph, not runtime signal tracking

A declared dependency graph is a signal graph that can be serialised, validated, and shared. Runtime read-tracking cannot. Runtime

D-012 active

Aggregation is declared; implicit fan-in stays forbidden

Spreadsheets need SUM(A1:A10), which is many-into-one. A declared fold gives it without reopening the door to implicit merging. Composites

Definitions and language

D-027 active

JS/TS first, WASM second, no native libraries

In an agent-operated platform the authoring language is the one agents write best. WASM covers performance; native libraries would break the sandbox and portability at once. Processes

D-028 active

Terminology and retention

Published versus embedded definitions, run retention, and the list of amendments to the original handoff. The document

Authority

D-042 active

Policy is a template in the World; bindings are session state

A World must carry its rules to be portable; identities are deployment-specific. Relationships

D-043 active

Four verbs, three scopes, deny by default

deliver, read, mutate, run over world, entities, or endpoints. A grant on a Composite never reaches its members. Relationships

D-044 active

Authority is checked once, at the boundary

Re-checking per hop would make delegation impossible and authority depend on route shape. Relationships

D-045 active

The file holder is not governed by policy

Whoever opens a World can edit it, including its policy. This is a multi-party session model, not a sandbox for untrusted documents. Relationships

Vocabulary

D-046 active

Blueprint, value type, appearance, Blockie state

"Type" was doing two jobs: the plan for a Blockie and the shape of a value. The plan is now a Blueprint; a BTS type is a value type; an archetype is an appearance; Model State is Blockie state. The decision log keeps the old words; living documents use the new ones. Blueprints

D-047 active

A Composite is a multi-cell widget with a Brain

Exactly one Brain Blockie, zero or more Parts, zero or more Members. The Brain owns the behavior; Parts render slices; Members are independent children. The Manager is a Run role, not the Brain. Gauge and Dashboard are patterns, not entity kinds. Composites

Validation

D-041 active

Repair is limited to dangling designation

Everything rejects except a manager designation left dangling by a crash, which is cleared with a diagnostic. The document
